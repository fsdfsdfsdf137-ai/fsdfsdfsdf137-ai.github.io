Контекст и решение

Согласовать список задач и состояние интерфейса

Задача

Собрать самостоятельное небольшое приложение, в котором задачи остаются доступными после перезагрузки, а поиск и фильтры не меняют исходный список.

Решение

Хранить полный массив задач отдельно от текущего фильтра и поискового запроса. При любом изменении данных сохранять массив, затем строить интерфейс заново из текущего состояния.

F · Техническая реализация

Данные отдельно, отображение — производное

Файлы реализации: index.html · css/style.css · js/main.js.

Структура HTML

Семантические header, aside, nav, main, section и footer. Для добавления используется форма; для статуса и действий — подписанные кнопки. Отдельные live regions сообщают об ошибках и состоянии хранилища.

Стили CSS

Grid делит экран на боковую панель и рабочую область, Flexbox выравнивает элементы управления. На компактном экране расположение становится вертикальным, а фильтры перемещаются к списку.

Логика JavaScript

В памяти хранится массив объектов с id, title, completed, createdAt и updatedAt. Функция фильтрации вычисляет видимые элементы без изменения исходного массива; render строит DOM и обновляет все счётчики.

DOM и события

Один обработчик на списке через делегирование обслуживает переключение статуса, редактирование, отмену и удаление. Формы добавления и редактирования обрабатываются submit-событиями, поэтому работает Enter.

Хранение и восстановление

Массив записывается в localStorage под версионированным ключом. При запуске JSON разбирается и проверяется; пустое хранилище даёт пустой список, повреждённая запись очищается, а исключения чтения/записи не роняют интерфейс.

Безопасность вывода и ошибки

Названия задач вставляются через textContent и createElement, не через innerHTML. Пустое название не добавляется, ошибка озвучивается и фокус возвращается в поле. Отсутствующее или повреждённое хранилище обрабатывается отдельно.

Адаптивность

При ширине до 820 px обзор и список переходят в одну колонку, боковые фильтры скрываются и показываются мобильные фильтры; до 560 px меняется плотность элементов и скрывается часть второстепенной навигации; до 360 px уменьшаются отступы. CSS задаёт эти переходы, но визуальный тест на реальных устройствах ещё не выполнялся.

Доступность

Есть skip-link, явные label, aria-label и aria-pressed для кнопок, live region, фокусная обводка, клавиша / для поиска и Escape для отмены редактирования. Анимации сокращаются при prefers-reduced-motion.

Пример восстановления данных

function loadTasks() {
  try {
    const saved = window.localStorage.getItem(STORAGE_KEY);
    if (saved === null) return;
    const parsed = JSON.parse(saved);
    if (!Array.isArray(parsed) || parsed.some((task) => !validTask(task))) {
      state.storageAvailable = false;
      window.localStorage.removeItem(STORAGE_KEY);
      return;
    }
    state.tasks = parsed.map((task) => ({
      id: task.id,
      title: task.title.trim(),
      completed: task.completed,
      createdAt: task.createdAt,
      updatedAt: typeof task.updatedAt === 'string' ? task.updatedAt : task.createdAt
    }));
  } catch {
    state.storageAvailable = false;
    state.tasks = [];
  }
}

Упрощённый фрагмент: фактический код нормализует каждую запись и отдельно защищает удаление некорректных данных.

G · Адаптивность и UX

Фильтры не теряют задачи, поиск не меняет данные

Создание работает кнопкой и Enter. Пустой ввод показывает сообщение вместо новой записи. Редактирование можно сохранить или отменить; удаление отдельной задачи происходит сразу, массовое удаление завершённых подтверждается. Фильтры доступны в боковой панели и компактном мобильном представлении. Поиск выполняется по названию, а сочетание фильтра и запроса сужает только видимый массив.

Счётчики всех, активных и завершённых задач рассчитываются из полного массива; видимое число относится только к результату фильтрации. Прогресс строится на доле выполненных задач. Пустые состояния различают новый список, пустой фильтр и отсутствие результатов поиска.

K · Итог

Личный список задач, который хранится в браузере

TaskFlow поддерживает создание, редактирование, удаление и выполнение задач, фильтры, поиск и счётчики. Проект показывает работу с состоянием и DOM, валидацию, безопасный вывод и локальное хранение. Ограничения: нет синхронизации между устройствами, аккаунтов или серверной копии; проверки в реальном браузере ещё предстоит провести.
